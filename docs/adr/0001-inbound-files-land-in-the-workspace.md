# 入站文件落进工作区，而不是落在工作区之外

聊天里发来的文件必须让 agent 读得到，而 agent 读文件的能力边界由部署方的 preset 和沙箱决定，本仓库无从得知。落在工作区之外（`~/.dsh/…`、`tmpdir`）的失败模式是不可观测的：部署方一旦收紧工具沙箱，症状只是模型说"读不到这个文件"，运维不知道该去改哪个配置。所以入站文件落进当前会话工作区下的 `.dsh-lark/inbox/`——代价是 `git status` 会变脏，但这个代价可见、可解释、用户自己能处理。

## Consequences

- 用户仓库会多出未跟踪文件。回复里要提示 `.gitignore`，但**不替用户改他的 `.gitignore`**。
- 文件跟着工作区走：`/cd` 之后旧文件留在旧目录。这是刻意的——文件属于项目，不属于聊天。
- 清理是用户的决定，渠道不设自动过期（同 epoch 机制"聊天命令不该能销毁记录"的原则）。
